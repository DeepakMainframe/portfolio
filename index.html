Model & Technical Foundations

Know the mechanics that affect design, quality, cost and speed.

01 · Tokens

Claude reads and generates text as tokens. More tokens can mean more cost, context usage and latency.

🖥️ Mainframe: Don't load every COBOL member when only 3 are relevant.

02 · Context Window

A bounded working space for instructions, conversation, files and tool results.

🖥️ Mainframe: Give Claude the relevant program, copybook and SQL—not the whole application.

03 · Sampling & Non-determinism

LLM output can vary, so test important behavior—not just exact wording.

🖥️ Mainframe: COBOL regression tests expect stable behavior; AI evals need tolerance for valid variation.

04 · Model Selection

Choose for capability, speed, volume and cost. Bigger is not always better.

🖥️ Mainframe: Use stronger reasoning for complex dependency analysis; lighter models for simple classification.

05 · Reasoning Mode

Deeper reasoning can help multi-step tasks, but may increase cost and latency.

🖥️ Mainframe: “Explain this MOVE” is simpler than tracing COBOL → copybook → DB2 → JCL.

06 · Zero / One / Multi-shot

Zero = no examples. One = one example. Multi = several examples. Examples use context.

🖥️ Mainframe: Show 2 correct COBOL paragraph classifications before asking Claude to classify more.

07 · SDK vs REST

SDKs add language-specific convenience; REST exposes the HTTP API directly.

🖥️ Mainframe: Think of choosing the integration style that best fits a CICS/service workflow.

08 · Sync / Streaming / Async

Sync waits. Streaming returns progressively. Async suits longer or high-volume work.

🖥️ Mainframe: Interactive CICS-style work differs from a large nightly batch process.
Remember: model + context + prompting + access pattern are core design choices.

Prompting, Tools & Agents

Build workflows that are clear, bounded and testable.

Instruction + Context + Examples + Constraints → Behavior

01 · System Prompts

Define role, behavior and boundaries.

Review this COBOL program.
Use supplied files as evidence.
Separate facts from assumptions.
Do not invent dependencies.

Output: behavior, rules, unknowns.

02 · XML & Structure

Separate task, context, examples, constraints and output.

🖥️ Mainframe: Keep COBOL source, copybook and business requirement clearly separated.

03 · Few-shot Examples

Use representative examples to show the behavior you want.

🖥️ Mainframe: Give a correct example of a “business rule” paragraph.

04 · Constraints & Output

Define required fields, limits and what to do when evidence is missing.

🖥️ Mainframe: Require Program, Copybooks, DB2 Tables, Rules and Open Questions.

05 · Diagnose Weak Prompts

Check ambiguity, missing context, missing examples, unclear output and model fit.

🖥️ Mainframe: If SQL is absent, don't ask Claude to “discover” a DB2 table from a field name.

06 · Tool Schemas

Describe a tool's purpose, inputs, outputs and failure cases precisely.

🖥️ Mainframe: find_program_dependency(program_name) should return defined evidence—not guesses.

07 · Tool-use Loop

Goal → Tool → Result → Next

The application validates calls and handles failures.

08 · Multi-turn & Thinking

Each turn can add context and tool results. Manage cost, latency and failure paths.

🖥️ Mainframe: First find the program, then inspect copybooks, then trace dependencies.

09 · Production Agents

An agent can decide and use tools across multiple steps.

ModelToolsMemoryHuman
🖥️ Mainframe: COBOL → copybooks → JCL → DB2 → impact report.

10 · Memory & Human Review

Choose what state persists. Put people at high-impact checkpoints.

🖥️ Mainframe: AI may prepare a DB2 change; approval comes before execution.
Remember: structured context + defined tools + explicit boundaries.

Permissions should match risk.

Review logic, assumptions, tests, security and operational impact.

🖥️ Mainframe: check PIC handling, DB2 errors and regression impact.

🖥️ Mainframe: keep rules for COBOL, copybooks and JCL analysis.

Package successful workflows for repeatable use.

🖥️ Mainframe: turn your COBOL review process into a reusable workflow.

MCP standardizes connections between Claude and external capabilities.

07 · Transport & Scope

Communication method and configuration scope affect how an integration is used.

🖥️ Mainframe: distinguish personal developer access from enterprise shared access.

Control identity, credentials, authorization and data boundaries.

🖥️ Mainframe: Claude should respect the same access boundaries as the authorized user/system.

Prove the system works

Measure quality, control risk and plan for failure.

01 · Evals

Define “done” and test representative tasks and failures.

InputSystemExpectedResult
🖥️ Mainframe: test nested PERFORMs, DB2 SQL, missing copybooks and file status.

02 · Test Variation

Evaluate important properties, not one exact sentence.

🖥️ Mainframe: two explanations can differ in wording and still describe the same flow.

03 · Tracing

Inspect instructions, model output, tool calls and tool results.

🖥️ Mainframe: trace which source search produced the wrong dependency.

04 · Cost Budget

Model, context, reasoning and workflow design affect cost.

🖥️ Mainframe: filter 20,000 programs first; use stronger reasoning only where needed.

05 · Latency

Multiple model turns and tools can add response time.

🖥️ Mainframe: one paragraph explanation can be interactive; a dependency scan can be async.

06 · Reliability

Plan for timeouts, invalid inputs, incomplete results and interruptions.

🖥️ Mainframe: if source search fails, report it—never invent a dependency.

07 · Prompt Injection

Retrieved content can contain instructions that try to manipulate the model.

Rule: data is not automatically authority.
🖥️ Mainframe: a malicious source comment is still source data.

08 · Secrets & Least Privilege

Protect credentials and give tools only the access they need.

🖥️ Mainframe: code analysis needs read access—not production DB write access.

09 · Human Review

Use people where errors are expensive or irreversible.

🖥️ Mainframe: developer/SME validates AI-generated change analysis before release.
Production: Quality → Evals → Security → Cost → Latency → Reliability → Observability → Human review
Remember: production readiness is evidence.

Make the solution reusable

Turn a working build into something others can understand and use.

01 · Prototype → Accelerator

Capture repeatable steps instead of keeping the solution in one person's prompt history.

🖥️ Mainframe: package a repeatable COBOL documentation workflow.

02 · Configuration

Separate environment-specific settings from reusable logic.

🖥️ Mainframe: keep repository and environment details outside the core workflow.

03 · Documentation

Document behavior, inputs, permissions, assumptions, evals and operations.

🖥️ Mainframe: document source members, copybook resolution and DB2 dependency rules.

04 · Deployment

Where it runs affects connectivity, security, data, latency, cost and operations.

🖥️ Mainframe: workstation, CI and enterprise-hosted deployments may need different access paths.

05 · Shared Infrastructure

Shared assets are easier to review, maintain and extend.

🖥️ Mainframe: five teams should reuse the workflow without your personal prompt history.
Remember: build once → document → evaluate → control → reuse.

01 · FOUNDATION

🧠 What is Claude?

What is it?

Claude is an AI assistant from Anthropic. It uses large language models to understand instructions, work with context, reason through problems and generate useful outputs.

Why does it matter?

Instead of interacting only through fixed commands, you can describe a goal in natural language and collaborate with Claude through an iterative conversation.

💡 Mental model

Traditional software: predefined rules → input → deterministic processing.

Claude: instruction + context + model reasoning → generated response.

AI output is not automatically a fact. Important results should be validated.

Example

Instead of asking only “What does this COBOL paragraph do?”, ask Claude to explain it step by step, identify possible business rules and list questions to confirm with an SME.

Key takeaway: Claude is a reasoning assistant, not a replacement for human validation.
02 · COLLABORATION

💬 Your First Conversation

What is it?

Claude understands natural-language instructions. You can start with a request and then refine the result through follow-up questions.

Why does it matter?

You do not need to write the perfect prompt on the first attempt. Good interaction is often iterative: ask → inspect → clarify → improve.

1Give Claude the task.
2Review the response.
3Point out what needs changing.
4Ask for the improved version.
Key takeaway: Think of Claude as a smart colleague you can iterate with.
03 · CORE SKILL

✍️ Getting Better Results — Prompting

A useful starting formula is:

Task + Context + Desired Result

Task

What do you want Claude to do?

Context

What information does Claude need to do it well?

Desired result

What should the output look like? Include format, audience, depth or constraints.

📋 Copyable developer prompt
I'm reviewing an existing COBOL program.

Please:
1. Explain this paragraph step by step
2. Identify apparent business rules
3. Flag hardcoded values and edge cases
4. List questions I should confirm with an SME
5. Clearly separate facts from assumptions

Code:
[PASTE CODE HERE]
⚠️ Validate inference. If Claude infers a DB2 table or copybook relationship from a field name, treat that as a hypothesis unless the actual source supports it.
Key takeaway: Specific context and a clear output format usually produce more useful results.

05 · CONTEXT

📁 Projects

What is it?

A Project is a dedicated workspace for a subject or goal. It can keep related conversations, files and instructions together.

Why does it matter?

Repeatedly explaining the same background wastes time. A focused workspace gives Claude the context needed for ongoing work.

Example project

Customer Billing Analysis — COBOL programs, copybooks, JCL, DB2 documentation, requirements and project instructions.

Key takeaway: Chat is a conversation; a Project is a workspace built around a continuing goal.
06 · CREATION

🎨 Artifacts

What are they?

Artifacts are substantial outputs Claude creates for you, such as documents, code, diagrams, visualizations or interactive content.

Why do they matter?

You can review the result, give feedback and iterate instead of treating the first response as the final product.

Example

“Create a design-ready flow showing COBOL → DB2 → CICS interactions. Then add JCL dependencies and identify areas requiring SME confirmation.”

Key takeaway: Artifacts turn a conversation into something you can inspect, refine and use.
07 · REUSE

🧩 Skills

What are they?

Skills are reusable instructions, capabilities or workflows for recurring types of work.

Prompt

An instruction for a particular task.

Skill

A reusable workflow or capability for repeated task types.

Example

A “COBOL Code Review” skill could consistently check business rules, error handling, DB2 interactions, copybooks, hardcoded values and potential risks.

Key takeaway: If you repeatedly do the same kind of work, turn the workflow into something reusable.
08 · INTEGRATION

🔌 Connecting Your Tools

Claude can work with connected tools and external systems, depending on the environment and permissions you provide.

User→Claude→Tool→External System→Result→Claude

Where can this help?

Examples include source repositories, files, project systems, collaboration platforms and other enterprise data sources.

🔐 Security principle: use least privilege. A connected tool should have only the access needed for the task.
MCP in one sentence

Model Context Protocol (MCP) provides a standardized way for AI applications to connect with tools and data sources.

Key takeaway: Tool access expands what Claude can do, but permissions and security still matter.
09 · KNOWLEDGE

🏢 Enterprise Search

What is it?

Enterprise search helps Claude find and synthesize information from connected organizational knowledge sources.

Why does it matter?

Important knowledge is often distributed across documentation, policies, project pages and other internal sources.

Example

Ask Claude to find the relevant design guidance across connected enterprise documentation and summarize the applicable points.

Remember: enterprise search does not mean Claude automatically sees everything. Identity, permissions and connected-source access still apply.
Key takeaway: Search makes organizational knowledge easier to retrieve and synthesize — within the access you provide.
10 · INVESTIGATION

🔎 Research for Deep Dives

Use research-style workflows when a question requires investigation, multiple sources, comparison and synthesis.

Simple question

Use a normal conversation when one clear answer is enough.

Deep investigation

Research when you need multiple sources, trade-offs, evidence and a synthesized conclusion.

Good research question

“Compare three approaches for exposing an existing transaction-processing application to modern consumers. Evaluate security, operational complexity, maintainability and migration risk.”

Validate important claims: especially technical, security, architecture, performance and cost conclusions.
Key takeaway: Use research when the task is investigation, not just question answering.

13 · PUTTING IT TOGETHER

These concepts become most useful when combined into one repeatable workflow.

1Start with a Project
Collect the relevant context and instructions.
2Ask clearly
Define the task, context and desired output.
3Inspect the result
Separate facts, assumptions and open questions.
4Iterate

Key takeaway: The power is not one feature — it is the workflow connecting context, prompting, creation, tools and validation.
